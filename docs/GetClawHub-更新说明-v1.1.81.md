# GetClawHub Mac 客户端 · 更新说明（v1.1.81）

一句话：**升级网关不会再把你的网关搞停；真出问题时，界面会直接告诉你原因。**

---

## 这一版修的是什么

客户端每次启动会检查内置的 OpenClaw 网关核心是否需要升级。在少数机器上（尤其是装了本地插件、或从很老的版本一路用过来的），新核心装上后起不来 —— 而旧的处理方式会把问题放大：

| 场景 | 之前 | 现在 |
|---|---|---|
| 新核心不接受你的配置 | 先停网关、换核心，起不来才发现 | **换之前先问过新核心**，不接受就完全不动，网关一秒不停 |
| 新核心装上但起不来 | 有时被误判成「升级成功」，留在坏状态 | 必须网关**真的应答**才算成功，否则回滚 |
| 升级失败 | 立刻重试，每次开客户端都停一次网关 | 记住失败，**24 小时内不再自动重试** |
| 回滚 | 只还原核心，配置仍是新版写的，旧版拒绝接管服务 | 配置一并还原（新版那份留档备查） |
| 升级中途退出客户端 | 停在半升级状态，无人收尾 | **下次启动自动收尾**：健康就保留，不健康就回滚 |
| 已经是最新版 | 有时仍白跑一整轮停机交换 | 直接判定「已是最新」，不碰网关 |
| 网关起不来 | 界面只显示「未运行」 | 直接显示**原因**（如「配置无效：channels.dingtalk …」） |

---

## 最后一条尤其值得说

以前网关起不来，界面只有一个灰点和「Stopped」。真正的原因写在系统日志里 —— 而当前版本的服务配置把错误输出丢弃了，**原因等于没有留下**。

所以这一版改成主动去问：网关不服务时，客户端自己跑一次配置校验，把校验器的原话显示在左上角。像下面这种，一眼就知道该改哪里：

> **Error** — Service process exists but gateway port 18789 is not listening — OpenClaw config is invalid: `channels.dingtalk: must not have additional properties: "robotCode"`

---

## 附：如果你的网关确实起不来

多半是插件相关。两类常见原因：

1. **本地路径安装的插件**（从 Downloads 之类的目录装的）。新核心校验更严，可能直接拒绝。改用 npm 上的正式包通常就好了。
2. **渠道配置跟不上插件新版本**。比如钉钉插件升级后不再接受 `robotCode`（它会自己从 `clientId` 推导），`agentId` 也从字符串改成数字。

现在这两类都会在界面上写明是哪个键的问题，不用再翻日志。

---

## 升级方式

菜单栏 **GetClawHub → 检查更新**，或重启客户端自动提示。
