# GetClawHub Mac 客户端 · 更新说明（v1.1.86）

一句话：**点停止后，半截回复仍显示在当前对话里，但不会再当作下一轮的上下文；停止过程中再发送会等切枝完成再直发，不会排进队列。**

---

## 这一版修的是什么

上一版把断线、网关重启后的「不重复发送、不把别的回合回复算到当前这条」做稳了。这一版收的是**点停止之后的下一轮上下文**。

以前点停止，界面上的半截助手回复会留下来，OpenClaw 会话文件里那条被中止的助手消息也还在当前枝上。下一次再发送，模型仍会把它当成上一轮回复来接着写，容易顺着半截内容跑偏。

### 1. 停止后把会话枝切回这条用户消息

点停止并且网关确认这次运行已经中止后，客户端会在本机 OpenClaw 的 jsonl 会话末尾追加一条 `leaf`，目标是**被停止的那条用户消息**（对齐 Windows 客户端的停止隔离）。

效果是：

- 半截助手回复还在当前对话里，方便你看已经生成了什么。
- 下一条直接发送时，不再把这条被中止的助手回复当作模型上下文。
- 如果会话里已经出现了更新的用户消息，不会把枝往回切。
- 同一条已经切过，不会重复追加。

### 2. 停止过程中再发送：等切枝完成再直发

点停止到切枝完成之间，如果在同一会话里再按发送：

- 先等这次停止走完（含切枝）。
- 成功后把输入框内容原样发出去，**不进排队**。
- 不会跟「正在发送」那条路径抢，避免半截回复还在枝上时就发出下一轮。

## 新安装与已有安装

- 新安装、已有安装：升级到 1.1.86 后直接使用，没有额外配置步骤。
- 不要求重装 Node，也不要求再点「安全修复网关」。

---

## 变更边界

只改 GetClawHub 客户端在停止聊天后对本机 OpenClaw 会话文件的切枝，以及停止过程中的发送时机。**不包含对 OpenClaw 网关核心仓库的修改**，捆绑核心仍是 `2026.7.1-2`。

---

## 升级方式

菜单栏 **GetClawHub → 检查更新**，或重启客户端自动提示。
