# GetClawHub Mac 客户端 · 更新说明（v1.1.82）

一句话：**内置网关核心对 Node.js 的要求是一组「区间」而不是一个最低版本——这一版按区间正确判断，装对 Node 再换核心；万一网关因为 Node 版本起不来，界面会直接告诉你原因。**

---

## 这一版修的是什么

OpenClaw 网关核心（2026.7.x）能跑的 Node.js 不是「大于等于某个版本」，而是一组**互不相连的区间**：

> `>=22.22.3 <23`，或 `>=24.15.0 <25`，或 `>=25.9.0`

也就是说 **Node 23.x 整个不要、Node 25.0–25.8 也不要**，哪怕它们比 24.15 还新。核心的启动器会卡住这个检查，不满足就直接退出。

而上一版客户端把它当成一个「最低版本 ≥ 24.15」来处理，于是出现了几类不该发生的情况：

| 场景 | 之前 | 现在 |
|---|---|---|
| 本机 Node 是 25.0–25.8（比 24.15 新，但核心照样拒绝） | 判定「满足要求」→ 换上新核心 → 网关起不来、launchd 反复拉起 | 按**真实区间**判断 → 发现不在支持范围 → 先装回内置 Node 再换核心 |
| 升级时连内置 Node 本身都不满足新核心 | 照样换上核心，留下一个永远起不来的网关 | **换之前先校验内置 Node**，不满足就**拒绝换核心**（旧核心仍在，网关一秒不停） |
| 普通启动网关时本机 Node 不被当前核心支持 | 网关一启动就退出，launchd 反复拉起，界面只显示「未运行」 | 启动前先检查 → 不兼容就**自动重装内置 Node** → 网关正常起 |
| 网关因 Node 版本被核心拒绝而起不来 | 界面只显示「网关启动失败」，原因写在被丢弃的日志里 | 界面直接显示**原因**（如「Node.js >=25.9.0 is required (current: v25.3.0)」） |
| 强制修复（Force Repair） | 不检查 Node 兼容性 | 新增一步：报告本机 Node 是否被当前核心支持，并在启动时自动修复 |

---

## 为什么以前会装「对」却起不来

核心的 Node 检查发生在**绑定端口之前**：不满足就 `process.exit(1)` 直接退出，一行业务日志都不写。于是会出现一种特别迷惑的现象——

- 核心升级报告「成功」；
- `launchctl` 显示网关「已加载」；
- 但网关每次启动即退出，被 launchd 无限拉起。

在系统层面一切看着「正常」，可网关就是不通。这一版从两头堵住：

1. **换核心前**：读懂真实区间，本机 Node 不在范围内就先装内置 Node；装完还要**再校验一遍**内置 Node 满不满足新核心——不满足就压根不换核心。
2. **网关起不来时**：客户端会直接跑一次核心的 `--version`，把启动器拒绝运行的原话显示在界面，不再让你对着一个「启动失败」干瞪眼。

---

## 老用户需要做什么

什么都不用做。客户端现在能识别核心声明的 Node 区间；旧版清单只有「最低版本」字段时，也会自动按「≥ 该版本」兜底处理，不会误伤。

---

## 升级方式

菜单栏 **GetClawHub → 检查更新**，或重启客户端自动提示。
